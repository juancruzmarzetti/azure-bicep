conditions and loops can help make your Azure deployments more flexible.

in this class we will extend a bicep template by using conditions and loops:
- use conditions to depoy resources only when required.
- use loops to deploy multiple instances of azure resources.
- control loop parallelism.
- create nested loops.
- combine loops with variables and outputs.

deploy resources conditionally: using conditions in the bicep code to deploy resources only when specific constraints are in place.

we can use the if keyword followed by a condition, for example:

param deployStorageAccount bool

resource storageAccount 'Microsoft.Storage/storageAccounts@2023-05-01' = if (deployStorageAccount) {
  name: 'teddybearstorage'
  location: resourceGroup().location
  kind: 'StorageV2'
  // ...
}

a more general example:

resource asd "Microsoft.Storage..." = if (condition) {

}

other type of condition example:


@allowed([
  'Development'
  'Production'
])
param environmentName string

resource auditingSettings 'Microsoft.Sql/servers/auditingSettings@2024-05-01-preview' = if (environmentName == 'Production') {
  parent: server
  name: 'default'
  properties: {
  }
}


depend on conditionally deployed resources: how bicep evaluates the dependecies between the resources?
a resource depends on other resource when we reference on one resource some data from other resource, and the deployment could fail if a resource depends on other resource that is defined using conditions.
In that case, in the second resource which depends on the conditionally defined one, in the part where we are referencing the data from the other resource, we should also make this reference conditional:
example:

resource auditingSettings 'Microsoft.Sql/servers/auditingSettings@2024-05-01-preview' = if (auditingEnabled) {
  parent: server
  name: 'default'
  properties: {
    state: 'Enabled'
    storageEndpoint: environmentName == 'Production' ? auditStorageAccount.properties.primaryEndpoints.blob : ''
    storageAccountAccessKey: environmentName == 'Production' ? listKeys(auditStorageAccount.id, auditStorageAccount.apiVersion).keys[0].value : ''
  }
}

deploy multiple resources by using loops: often, you need to deploy multiple resources that are very similar.

use copy loops. when you define a resource or a module in a bicep template you can use the for keyword to create a loop.
for example: we want to create 3 storage accounts with the same properties but with different names, so:

param storageAccountNames array = [
  'saauditus'
  'saauditeurope'
  'saauditapac'
]

resource storageAccountResources 'Microsoft.Storage/storageAccounts@2023-05-01' = [for storageAccountName in storageAccountNames: {
  name: storageAccountName
  location: resourceGroup().location
  kind: 'StorageV2'
  sku: {
    name: 'Standard_LRS'
  }
}]


loop based on a count: its good to use this kind of loop when you need to create a specific number of resources, and not use an array as the source.
when you use the range() function, you provide two arguemnts: 
- the first specifies the starting value
- the second tells bixep the number of values you want.
for example: if you use range(3,4) then bicep will return the values 3, 4, 5 and 6.

Access the iteration index: you can iterate through arrays and retrieve the index of the current element in the array.
for example:

@description('The Azure regions into which the resources should be deployed.')
param locations array = [
  'westus'
  'eastus2'
]

module databases 'modules/database.bicep' = [for location in locations: {
  name: 'database-${location}'
  params: {
    location: location
    sqlServerAdministratorLogin: sqlServerAdministratorLogin
    sqlServerAdministratorLoginPassword: sqlServerAdministratorLoginPassword
  }
}]

you can also reference every item of an array with its associated index, like "locations[0]" value would be "westus"

using a specific syntax you can use the value of an array property and simultaneously reference its associated array index:

resource sqlServers 'Microsoft.Sql/servers@2024-05-01-preview' = [for (location, i) in locations: {
  name: 'sqlserver-${i+1}'
  location: location
  properties: {
    administratorLogin: administratorLogin
    administratorLoginPassword: administratorLoginPassword
  }
}]


we also could want to, in a bucle, filter the array to use some properties or objects of the array instead of others...

param sqlServerDetails array = [
  {
    name: 'sqlserver-we'
    location: 'westeurope'
    environmentName: 'Production'
  }
  {
    name: 'sqlserver-eus2'
    location: 'eastus2'
    environmentName: 'Development'
  }
  {
    name: 'sqlserver-eas'
    location: 'eastasia'
    environmentName: 'Production'
  }
]

resource sqlServers 'Microsoft.Sql/servers@2024-05-01-preview' = [for sqlServer in sqlServerDetails: if (sqlServer.environmentName == 'Production') {
  name: sqlServer.name
  location: sqlServer.location
  properties: {
    administratorLogin: administratorLogin
    administratorLoginPassword: administratorLoginPassword
  }
  tags: {
    environment: sqlServer.environmentName
  }
}] 

for the deploy we should run the following on Azure CLI:

az deployment group create --name main --template-file main.bicep


Control loop execution using @batchSize:
when we deploy multiple resources, by default, ARM deploys most of them simultaneously. But in some cases we should want to deploy them in a controlled sequence, and organize its deployments.

for example:

@batchSize(2)
resource appServiceApp 'Microsoft.Web/sites@2024-04-01' = [for i in range(1,3): {
  name: 'app${i}'
  // ...
}]

there, "app1" and "app2" will be deployed in the first batch, and when that deployment ends, the "app3" will start to be deployed in the second batch.
in general, this is used in some specific resources.

other example:

@batchSize(1)
resource appServiceApp 'Microsoft.Web/sites@2024-04-01' = [for i in range(1,3): {
  name: 'app${i}'
  // ...
}]

then, you can use lopps to help set resource properties:

for example, you can use array indexes for subnets address prefixes:

param subnetNames array = [
  'api'
  'worker'
]

resource virtualNetwork 'Microsoft.Network/virtualNetworks@2024-05-01' = {
  name: 'teddybear'
  location: resourceGroup().location
  properties: {
    addressSpace: {
      addressPrefixes: [
        '10.0.0.0/16'
      ]
    }
    subnets: [for (subnetName, i) in subnetNames: {
      name: subnetName
      properties: {
        addressPrefix: '10.0.${i}.0/24'
      }
    }]
  }
}

Nested loops:
some scenarios need you to use a loop inside another lopp: a nested loop...

example:

resource virtualNetworks 'Microsoft.Network/virtualNetworks@2024-05-01' = [for (location, i) in locations : {
  name: 'vnet-${location}'
  location: location
  properties: {
    addressSpace:{
      addressPrefixes:[
        '10.${i}.0.0/16'
      ]
    }
    subnets: [for j in range(1, subnetCount): {
      name: 'subnet-${j}'
      properties: {
        addressPrefix: '10.${i}.${j}.0/24'
      }
    }]
  }
}]

this would create 3 virtual networks, each one with its associated location, a address prefix and two subnets.

Variable and output loops:

variable loops: by using them you can create an array, which you can then use through your bicep file.
for example:

var items = [for i in range(1, 5): 'item${i}']

other example:

param addressPrefix string = '10.10.0.0/16'
param subnets array = [
  {
    name: 'frontend'
    ipAddressRange: '10.10.0.0/24'
  }
  {
    name: 'backend'
    ipAddressRange: '10.10.1.0/24'
  }
]

var subnetsProperty = [for subnet in subnets: {
  name: subnet.name
  properties: {
    addressPrefix: subnet.ipAddressRange
  }
}]

resource virtualNetwork 'Microsoft.Network/virtualNetworks@2024-05-01' = {
  name: 'teddybear'
  location: resourceGroup().location
  properties:{
    addressSpace:{
      addressPrefixes:[
        addressPrefix
      ]
    }
    subnets: subnetsProperty
  }
}

using loops for declaring output variables: 

for example:

var items = [
  'item1'
  'item2'
  'item3'
  'item4'
  'item5'
]

output outputItems array = [for i in range(0, length(items)): items[i]]

other example:

param locations array = [
  'westeurope'
  'eastus2'
  'eastasia'
]

resource storageAccounts 'Microsoft.Storage/storageAccounts@2023-05-01' = [for location in locations: {
  name: 'toy${uniqueString(resourceGroup().id, location)}'
  location: location
  kind: 'StorageV2'
  sku: {
    name: 'Standard_LRS'
  }
}]

output storageEndpoints array = [for i in range(0, length(locations)): {
  name: storageAccounts[i].name
  location: storageAccounts[i].location
  blobEndpoint: storageAccounts[i].properties.primaryEndpoints.blob
  fileEndpoint: storageAccounts[i].properties.primaryEndpoints.file
}]
